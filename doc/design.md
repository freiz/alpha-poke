## 1. 目标与约束

**目标**：Gen9 OU 单打的强力对战 AI，水平接近或超越人类 pro；本地训练与评测（Python + uv + poke-env + 本地 Showdown，搜索与推理在自有 Rust crate）。同时探索新算法，两个研究方向：
- **A. 语言模型产生 MCTS 可用的先验**（策略或价值）；
- **B. 隐藏信息有机地融入 MCTS**（不只是"采样后各搜各的"）。

**非目标**：每回合调用 LLM 的在线策略（R§8.4）；双打 / VGC；其他世代。组队在计划内但不是当前重点（D5）。

**约束**
- 服务器：评测和训练只用本地 Showdown（`alpha_poke.servers.local_server` 只允许本机地址）。唯一例外是 `scripts/play_public.py --public`，只接受白名单对手的挑战，不上天梯、不进房间、不主动挑战。公共天梯只用于最终评测，原则见 D7。
- 许可：Foul Play 为 GPL-3.0，只作为外部进程对手，不 import、不复制代码；poke-engine（MIT）作为库依赖；Metamon 数据集 CC-BY-NC-4.0，Metamon 原始 replay 只用于本地研究、不再分发。
- 密钥在 `.env`（OpenRouter key、公共服务器账号），不打印、不入库。
- LLM：全局预算 `LLM_BUDGET_USD`；跑 LLM bot 的评测前先核对计划缓存覆盖。

## 2. 问题特性

双人零和、**不完全信息**（对手配置隐藏，队伍预览只见 6 只物种）、**同时出招**（每回合约 9×9 的矩阵博弈，最优解常是混合策略）、随机性大（伤害浮动、会心、命中）、长时程（几十到上百回合）。没有 OTS：招式、道具、特性、太晶在对局中逐步暴露，努力值 / 性格永不可见。因此对手配置的信念模型和"怎么在搜索里用它"是核心问题。

## 3. 当前系统

```
poke-env（协议、局面跟踪）──► SearchPlayer（Python 薄适配层）
                                 │ 信念模型采样 N=32 个对方配置（整队条件先验 × 套路，β=1）
                                 ▼
                        alpha_search（Rust，释放 GIL）
                        SO-ISMCTS：一棵树、每次迭代换一个世界、开环随机
                        PUCT：双方先验 = 策略网络（对方用翻转视角前向）
                        叶子：价值网络（残差：手写评估的线性项 + 网络）
                                 │ 我方根访问分布
                                 ▼
                        指令；任何失败 → KnowledgePlayer 的启发式决策
开局：KnowledgePlayer 的规则计划只决定首发（LLM 已关闭）
```

- **当前最强配置**：`s_ismcts_pv`（ISMCTS + v1 中档 MLP 的价值和双方先验，500 ms 单线程）。对只用手写评估的 ISMCTS 胜率 66.3%（+117 Elo），对确定化搜索更强（ISMCTS 对确定化 57.3%）。对 Foul Play 还没测。
- **离线最好的网络**：Transformer + 8 步历史 + MTP-3，只在 10% 的数据上训练过，还没接进搜索（Rust 推理未实现）。
- **公共对战脚本**的三档仍是旧版（启发式 / 确定化搜索），待换成 ISMCTS + 网络。

## 4. 设计决策

### D1. 目标赛制 —— 已定

Gen9 OU 单打。随机对战不需要组队，人类水平被拉低，不足以衡量 pro 水平；Gen9 OU 人口最大，也没有公开的顶尖 RL agent。

### D2. 基础设施 —— 已定

- **对战环境**：poke-env + 多个本地 Showdown 服务器，训练和评测共用一条路径。本机约 3.8k 回合/秒，不含网络推理（`results.md`）。单个服务器上限约 1.3k 回合/秒，直驱 `BattleStream` 只快约 1.6 倍。
- **前向模型**：poke-engine 0.0.48（`gen9` + `terastallization`）。搜索中当作近似模型，不作为训练真值。
- **自写快引擎暂不做**：等自对弈规模需要 10^8 局、Showdown 吞吐成为瓶颈时，再按实测决定。
- **Python / Rust 分工**：
  - Rust（`rust/alpha_search`，pyo3 + maturin，uv 本地包，改 Rust 代码后 `uv run` 会自动重编）：每步决策里反复跑的计算，即搜索、特征化、网络推理。
  - Python：协议、局面跟踪、信念采样（每个世界约 1 ms，其时间从搜索预算中扣除）、训练、评测、分析。
  - 接口是粗粒度的：每步调用一次，传局面字符串和 numpy 缓冲区。Rust 的 panic 在 Python 侧转成异常，然后退回启发式。
- **整体改用 Rust 的时机**：自对弈需要上百万局、poke-env 成为瓶颈时。
- **poke-engine 的使用方式**：从 crates.io 按 `=0.0.48` 固定版本作依赖，不 fork；需要改动时用 `[patch.crates-io]`。

### D3. 算法路线 —— 已定

- **AlphaZero 式**：信息集 MCTS（D12）+ 策略 / 价值网络（D13）。
- **不用 alpha-beta + NNUE**：同时出招的最优解常是混合策略，期望节点让剪枝失效，而且两者都以完全信息为前提。搜索的主要开销在展开回合，而不在评估。
- **训练顺序**：先人类数据（行为克隆 + 胜负），再 expert iteration 自对弈，不从零开始自对弈。理由：
  - 算力差距大；
  - 从零开始容易收敛到"对付自己"的打法；
  - 最终对手是人类，人类数据能直接教会"对手会怎么出招"。
- **LLM 不进每回合决策**。LLM 作开局计划，在首发和根节点先验两种用法上都没有可测的价值，已关闭（代码保留）。方向 A 改为离线 / 每局一次的用法，见 D14-5/6/7。

### D4. 复用 vs 自研 —— 已定

- 核心栈自研。
- Metamon 和 Foul Play 作为基线与评测对手：Foul Play 已接入，用 `scripts/vs_foulplay.py`；Metamon checkpoint 待接入，需要独立 venv 和 flash-attn。
- 复用 Metamon 的数据，不复用它的代码。
- 信念推断规则 clean-room 重写，不使用 `data.foulplay.cc`。

### D5. 组队 —— 已定：先用人类队伍，组队学习放到 M5

**评测**：40 支队伍的固定池（`data/teams/pool`），用配对赛程。"heldout" 指信念模型的训练数据里不含池中队伍。

**自对弈的组队（方案，待实现）**。目标是无偏地覆盖线上流行组队：
- 从 Metamon / 自爬 replay 里**抽一局真实对局，用这局里双方各自的队伍**。抽样分布就是天梯的实际分布，热门队伍按出现频率自然覆盖；成对地抽保留了"同一分数段的队伍相遇"的相关性（天梯按分数匹配，两边的队伍都和分数相关），两边独立抽会产生很多现实里少见的组合。交换座位各打一次。这局的分数只用来抽队，自对弈的身份输入是 bot 的代数（D14-2）。
- 按时间切分：只用近期对局，并按时间加权，避开禁用名单的变化。
- 未暴露的配置用信念模型补全。
- 用 Smogon 使用率统计校验抽样后的物种和配置分布。
- 每对队伍只打一局，对局数用来覆盖更多的队伍对。

**自对弈的搜索设置（2026-10-07 讨论，数字待实测）**：
- 用 GPU，**跨对局批量**：同时下几十、上百局，每局的搜索是单线程的逐个搜索（没有 virtual loss，结果与 CPU 逐个搜索相同），叶子跨对局凑批给 GPU。每个叶子约 100 µs CPU，10 核约 10 万叶子/秒，约为 CPU 推理的 5 倍。
- **迭代数（实测，`results.md`）**：自对弈是为了生成训练数据，标准是"搜索结果比网络先验好多少"相对于成本。与深搜索的首选一致率 / 总变差：网络先验 47% / 0.406，1k 63% / 0.272，2k 70% / 0.230，3k 73% / 0.204，4k 78% / 0.184（上限约 82% / 0.148）。**定为完整搜索 3,000 次**（拿到先验到上限之间约三分之二的改进），配合搜索量随机化：25% 的决策完整搜索并产出策略目标，其余快速搜索 600 次，只用来下棋。
- **随机性（实测）**：根节点 Dirichlet 噪声（双方）**ε = 0.10，总浓度 10**（α = 10 / 选项数）。网格 ε ∈ {0, 0.1, 0.25, 0.4} × 总浓度 ∈ {3, 10, 30}：ε = 0.1 时目标质量没有下降、探索量 +1 个点；ε 到 0.25 后探索量几乎不再增加，目标变差（总变差 +0.02–0.05），探到的招里深搜索也认可的比例从约 77% 降到约 60%。噪声对我们的作用整体不大（同时出招和 32 个世界本身就带来探索）。实际下的招按访问分布采样（τ = 1，同时出招时更接近混合均衡）。

**后期方向**：队伍元博弈（PSRO / double oracle）、以对战胜率为奖励的配置生成器（R§8.5）。

### D6. 算力

- 本机：AMD 79xx（12–16 核）、64 GB 内存、RTX 4070 Ti 12 GB。可以租云。
- GPU 训练够用：v2s 的 Transformer 每秒约 8.7 万样本。瓶颈在 CPU，即搜索和模拟器。
- 自对弈规模上来后，优先考虑租多核 CPU。
- 大内存任务一次只跑一个，用 `systemd-run --user --scope -p MemoryMax=...` 限制内存（曾经 OOM 导致 WSL 崩溃）。

### D7. 评测协议

- **配对赛程**：固定种子生成队伍对，每对交换队伍各打一局，双方轮流发起挑战，报配对胜率 ± 95% CI。300 局约 ±5.3 个百分点；要检出约 2 个点的差别需要约 2000 局。
- **每次 arena 运行都写 `<log>.meta.json`**：commit、`ALPHA_*` 环境变量、bot 定义和汇总。`results.md` 的表由 `scripts/results_table.py --write` 生成。
- **外部对手**：Foul Play 10 ms × 1 作为灵敏档，1000 ms × 4 作为强档。另有旧版本回归（`scripts/vs_checkout.py`）。
- **离线评测**：锚点验证集为上传时间 ≥ 1776921722 的约 6k 局 / 7.2 万局面，所有 v1 / v2 模型都没训练过（`scripts/eval_pv.py`）。种子标准差约为策略 CE 0.003、价值 BCE 0.0025，单次运行 0.005 以下的差别不可信。
- **公共天梯**：只用于最终 checkpoint，用新开的、明确命名的账号，最多几百局，报 Glicko / GXE。

### D8. 对手信念模型

- **现行**：`belief/priors.py`。
  - 整队条件先验：认出被照搬的队伍 → 核心条件 → 物种分布，逐级回退。
  - 招式 = 物种套路后验 × 整队条件边缘^β，β=1（`ALPHA_MOVE_BETA`）。
  - 模型用 5 万局自爬 replay 构建，评测用 heldout 版。
- **有效结论**（离线数字见 `belief_prior_eval.md`、`results.md`）：
  - 整队条件先验明显优于 Smogon 边缘分布，道具 top-1 为 76.6% 对 55.4%。
  - β=1 把采样招式对之后暴露招式的覆盖率从 61.7% 提到 77.3%。
  - "上场 t 次还没用某招"这种负证据几乎没有增益，没有接入搜索。
  - 对局中对手实际动作只有约 80% 落在单个世界的选项内。
- **短板**：招式不确定性。oracle 分解显示，完全信息的价值几乎全在招式上。改进方向见 D14-3（学出来的信念 + 一致性过滤）。

### D11. 隐藏信息与 LLM 先验：已有结论

研究方向 A / B 的实验结论。下一步都转到 D12–D14。

- **完全信息的上界**：知道对方真实配置约 +8–12 个百分点，几乎全部来自招式（只给招式 57.5%；道具、太晶、努力值都不显著）。
- **确定化（K 份世界各搜各的）的内在矛盾**：世界的多样性和每棵树的深度争同一份预算，K=4–8 最优。这是改用 ISMCTS 的直接动机。ISMCTS 对确定化 57.3%。
- **LLM 开局计划没有可测价值**：
  - 启发式 bot 上，LLM 计划对规则计划 51%；
  - 搜索 bot 上，LLM 首发 47%，计划作根节点先验 47%。
  - 根节点后处理太浅，计划要起作用必须进入树内。

### D12. ISMCTS（`rust/alpha_search/src/ismcts.rs`）—— 现行

- **SO-ISMCTS**：
  - 一棵树建在我方信息集上，每次迭代轮换一个世界，在该世界的根局面上原地 apply / reverse。
  - 子节点的键是（我方行动标签, 对方行动标签）。对方招式按招式 id，换人按队伍位置，跨世界一致。
  - 选择用双方解耦的**可用性** UCB / PUCT：每个行动单独记录"可用次数"。
- **开环随机**：对 poke-engine MCTS 持平（`s_ismcts_n1` 50.7%）；前 2 层闭环（`chance_depth`，默认 0）无提升。
- **只缓存根节点的指令表**：开环下同一节点在同一世界里会以不同局面到达，而 poke-engine 的指令带绝对值。
- **PUCT**：`Q + c·P·√N/(1+n)`，FPU 取已访问分支 Q 的均值。我方先验来自叶子的那次前向；对方先验来自翻转视角的前向；只在后来的世界里出现的对方选项用均匀先验。
- **根并行**：`threads` 个独立的树，最后合并根统计；4 线程约 3.75 倍。
- **决策**：选我方根访问数最多的行动。
- **已知局限**：
  - 对方在树中按"看穿我方全部配置"出招（D14-1）。
  - 对方的统计跨世界平均（反向的策略融合）；正解是 MO-ISMCTS。
  - 树内不更新信念（D14-3）。
  - 搜索对搜索偶尔陷入无限换人的拖延循环（约每 300 局 1 局打到 1000 回合，TODO P1）。
  - 复活祝福无法表示，会退回启发式，约每 100 局 1–2 次。

### D13. 策略 / 价值网络与训练 —— 现行

**训练数据**：Metamon 原始 replay 里的 Gen9 OU 2,038,375 局（`data/metamon/gen9ou`），加上自爬 5 万局（只用于信念模型和评测）。
- `alpha_poke/train/positions.py`：逐行回放 replay，为抽中的决策点建单方视角的 poke-engine 局面。己方用整局暴露的信息加信念补全，招式顺序打乱；对方只用当时已暴露的信息加信念。
- 每个决策点的列：
  - 标签：实际行动（14 槽）；
  - 价值：是否获胜；
  - `history`：最近 8 个决策步；
  - `future`：之后 4 步双方的动作。
- 用 `scripts/build_training_data.py` 构建：按分片流式处理、可断点续跑、heldout 信念；设 `PYTHONHASHSEED=0` 保证可复现。
- **每局约 12 个局面**（约为全部决策点的 1/3）。策略头的每个决策都是独立标签；价值损失按局降权（`--value-per-game 4`），避免同局相关导致过拟合。
- **决策步**与 poke-engine 的决策节点一一对应：每回合一步、U-turn 等招式后的换人一步、倒下后的强制换人一步。每步每方记录出手者、招式（及是否太晶）、换上的宝可梦。
  - 训练时从 replay 得到；
  - 搜索时 = 真实历史 + 树中从根到叶的路径（`features::Act::of_choice`）。

**特征**：Rust `features.rs`，训练与搜索共用。
- 12 个实体：稀疏 id（物种 / 道具 / 特性 / 太晶 / 属性 / 4 招）+ 稠密特征；
- 全局特征：天气、场地、双方场地状态、能力等级、挥发状态；
- 14 槽合法动作掩码；
- 历史：8 步 × 每方（出手者、招式、换上的宝可梦、太晶）。

**模型**：
- 在搜索中用的是 **v1 中档 MLP**（47 万参数，残差价值：`logit = a·eval/100 + b + net`）。Rust 推理一次前向 51 µs，与 PyTorch 对齐。
- 离线最好的是 **`TransformerPV` + 8 步历史 + MTP-3**（60 万参数）：12 个实体 token + 1 个全局 token + 8 个历史 token，预归一化 3 层，d=128。价值头和策略头读全局 token，换人槽读己方实体 token。

**有效结论**（数字见 `results.md`）：
- **搜索中要价值和先验一起用**：
  - 先验约 +70 Elo，价值网络约 +47 Elo。
  - 只用价值网络时更弱（37%）：迭代数降到约 1/10，绝对胜率又压缩了动作之间的差距，UCB1 的根访问几乎是均匀的。
- **历史与 Transformer 叠加的效果大于各自之和**。只用 10% 的数据，策略就追平了全量训练的 v1，换人 top-1 从 21.8% 提到 25.1%。
- **历史长度到 8 步饱和**：8 / 16 / 32 步没有差别，存储上限也定为 8。
- **价值头受数据量限制**：10% 的数据下，几种结构的价值 BCE 都在 0.574 左右，全量 v1 为 0.563。
- **MTP-3 已采纳**（权重 0.5，按步衰减 0.5^k；`--mtp 3 --mtp-weight 0.5 --mtp-decay 0.5`）：
  - 价值 BCE −0.0056（2.5 SE），换人 CE −0.026（5.5 SE），主策略不变。
  - 权重 0.2 时主策略更好（−0.0075），但价值收益不显著。全量数据上再对比一次。
- **MTP 对手头还不能替代翻转视角**：预测对手实际动作的 top-1 为 43.6%，翻转视角为 48.6%。

**网络 v3 第一批：特征与输出（2026-10-06 决定，在 10% 数据上实验）**
- 现有特征的缺口：
  - 对手实体的招式 / 道具 / 特性 / 太晶是信念采样的，网络分不清已暴露的和猜的；
  - 招式只有编号的嵌入，没有属性、威力、先制度，冷门招式学不好；
  - 克制关系、先后手、伤害线都要网络自己从嵌入里组合出来。
- **A 组：已知 / 猜测与便宜的数值**
  - 每只宝可梦 8 位公开信息标记：上过场、道具 / 特性 / 太晶属性已暴露、4 个招式槽各一位。对手的标记 = 我们看到的；我方的标记 = 对手看到的（D14-1 的前提）。
  - 全局：回合数；天气 / 场地的剩余回合；每方的存活数、总 HP、太晶是否已用、上次使用的招式槽（讲究锁招）。
  - 招式静态属性表：属性、分类、威力、命中、先制度，以及接触、声音、回复、吸取、反伤、强化、异常、场地状态、换人等标志。从 poke-engine 的招式表导出，作为固定查表投影后加到招式嵌入上。
- **B 组：对阵计算**（Rust，用 poke-engine 的 `calculate_damage_rolls`）
  - 双方在场 4 招打对方在场的伤害占当前 HP 的比例（最大值，最小值取 0.85 倍），以及是否必定 / 可能击倒；
  - 每只宝可梦挨对方在场最强一招的伤害比例（后备里谁能安全换上）；
  - 有效速度（能力等级、围巾、麻痹、顺风、天气特性等）对对方在场的比值，以及谁先动（考虑戏法空间）；
  - 后备换上时挨的入场钉子伤害（隐形岩按属性，撒菱看是否着地；厚底靴 / 魔法防守免疫），以及是否一上场就倒下。
- **C 组：辅助输出**（只在训练时用）
  - 对手配置头：标签 = 整局最终暴露的道具、特性、太晶、招式，没暴露的不计损失；
  - 本步结束时双方在场的宝可梦是否倒下；
  - 终局双方剩余数量之差；
  - 剩余回合数。
- 数据 `v3s` 与 v2m 用同样的对局和抽样，新列一次加齐；基线是 MTP-3。A / B / C 逐组加，每组 3 个种子，有效的再合并。
- **结果**（2026-10-06，数字见 `results.md`）：
  - **B 组收益最大**：策略 CE −0.050（19 SE），top-1 +2.0 个点，换人 CE −0.030。击倒线、谁先动这类"乘法加阈值"的计算，网络很难自己从嵌入里学出来。
  - A 组：策略 CE −0.020，价值没有改善。
  - C 组：对主任务基本无作用（价值 +0.000）。基线里已经有 MTP 提供的正则，剩余数量之差和价值几乎是同一个标签。
  - **ABC 合并**：策略 CE −0.061，top-1 +2.5 个点，换人 CE −0.046，对手动作 top-1 +1.3 个点。
  - 价值头在 10% 数据上对所有改动都不灵敏（各组 ±0.002，第 12 回合起最多 −0.003），受数据量限制：验证价值在约第 2000 步后就不再下降。价值方面的结论要到全量数据上看。
  - 对手配置头在未暴露字段上比信念单次采样准（道具 64% 对 48%，太晶属性 41% 对 32%），但对比偏向网络（见 D14-3）。
  - **决定**：A、B 组的特征都并入全量训练。C 组的辅助头对主任务没有作用，但对手配置头保留，用于 D14-3。
- 搜索中的代价：A 只是查表；B 每个节点约 8 + 20 次伤害计算，需实测。公开信息标记在搜索里的来源（根节点取自真实对局，树中路径上用过的招式标为已暴露）等接入 Rust 推理时实现。

**网络 v4：补齐全量训练前的特征与数据（2026-10-07 决定，在 10% 数据上一起实验）**
- **玩家水平**（D14-2 的第一步）：
  - 双方赛前分数取自日志的 `|player|p1|名字|头像|分数` 行（Metamon 约 96% 的对局有，我们自爬的也有）。不用 Metamon 的 `rating` 字段，它和双方分数的最小值、平均值都对不上。
  - 输入 = 双方分数（标准化）、分差、是否已知。训练时按一定概率随机遮成"未知"，自对弈和不知道分数时也能用。
- **历史步的结果**：
  - 每方每步记：造成的伤害（对方在场 HP 的百分比）、会心、未命中 / 失败 / 无效、击倒、本步是否先动、被阻止（`|cant|`：麻痹、睡眠、畏缩、蓄力等）、行动前倒下。
  - 搜索树中的路径步暂时没有结果（全 0），等 Rust 推理时从引擎指令里取。
- **缺失的决策点**：
  - 倒下后的强制换人、U-turn 等招式后的换人：建局面（强制换人状态，合法动作只有换人），标签是换上的宝可梦。
  - 看不到动作的回合（被阻止 / 行动前倒下）：用部分标签（"某个招式槽"，是否太晶已知）。
  - 这些新增的决策点用独立的随机数生成器抽样（每局最多 8 个），原有的回合开始局面与 v3s 逐条一致。
- **B+ 换人克制特征**：
  - 每只后备挨"对方对我方在场最有效的那招"的伤害和击倒线；
  - 每只后备的最佳招式打对方在场的伤害。
- 两两 6×6 对阵矩阵搁置：每个局面约 300 次伤害计算，搜索中太慢。
- **"招式缺失"的诊断**（400 局，4,133 个对手动作）：
  - 对手实际招式不在世界里的 21.1% **全部是对手之前没用过、信念也没猜中的招式**，不是 bug；
  - 唯一一例"之前暴露过却不在世界里"是幻觉（Zoroark-Hisui 伪装成 Krookodile）。
  - 改进要靠信念（D14-3）和 32 个世界的合集覆盖。

- **v4 结果**（2026-10-07，数字见 `results.md`）与全量训练的配置：
  - 采纳 Elo（价值 −0.003，校准 ECE 0.023 → 0.016）、换人克制（强制换人 top-1 +1.3 个点，价值 −0.007）、强制 / U-turn 换人局面（强制换人 top-1 42% → 53%，价值 −0.010，无副作用）。
  - 看不到动作的回合（部分标签）：纠正了价值在"会被先手击倒"局面上的偏差（BCE 0.541 → 0.500），但主动换人被低估（CE +0.16）。原因之一是抽样率不一致：新决策点约 60%，回合开始约 28%，看不到动作的回合在训练里被多算约一倍。**下一步**：每个局面记录抽样权重（池大小 / 抽中数），训练和评估都按它加权，先在 10% 数据上验证。
  - 不采纳历史步结果：修复 bug 后仍无可测效果；局面里的 HP 已经反映了伤害，速度信息已在有效速度特征里，搜索端还要额外实现。整局累积的速度上下界推断留作后续。
  - **抽样权重的验证**（`results.md`）：按权重训练只部分纠正了主动换人的低估，在按真实比例的公平指标上反而略差（有效样本量变小）。**决定**：全量数据从每局所有决策点合成的一个池里统一抽 20 个（`--pool all`），各类决策点的比例天然和真实对局一致，不需要权重。
  - 全量训练用流式加载（`--stream K`）：内存只保留小列，每次读 K 个分片（Metamon 的分片在时间上随机混合），后台预读下一块；速度和全部放进内存时相同。
  - 评估和检查点选择都改用公平指标：全部回合开始的策略 CE（加权）+ 全部局面的价值 BCE（加权）。只看有出招记录的回合开始局面是有偏的。
  - 特征计算已改为多线程（批量接口），v4 的对阵特征约 18 µs / 局面，全量建缓存约 20 分钟。

**全量训练结果（2026-10-07，`results.md`）**：v5-final 对搜索中在用的 v1 MLP，策略 CE −0.19，价值 BCE −0.030，top-1 48.6% → 55.6%。同样全量数据下，v3 / v4 特征仍有收益，但比 10% 数据时小（策略 −0.020，价值 −0.004），需要在对战中权衡它在搜索里的特征计算成本。

**基线 `baseline-v5`（git tag，2026-10-07）**：网络结构实验之前的版本，以后的结构 / 特征 / 自对弈改动都和它比。
- 网络：`data/train/v5/runs/v5-final`（`best.safetensors` sha256 前缀 `61af7cb5ace200cf`；权重不入库），Transformer d=128、3 层、4 头，8 步历史，MTP-3，特征 reveal / num / movetab / matchup / elo / counter，对手配置头；全量 v5 数据，6 个 epoch。
- 离线（v5 锚点集）：回合开始策略 CE 1.129，价值 BCE 0.5277，top-1 / top-3 55.6% / 87.4%。
- 搜索：`s_ismcts_tfg`（GPU 树并行，批量 32 × 8 线程，流水线，32 个世界）。对战：CPU 版对 v1 MLP 58.0%（500 ms），GPU 版对 CPU 版 60.8%（107 局）；对 Foul Play 的结果见 `results.md`。

**推理与搜索接入（2026-10-07）**
- **Rust CPU 推理**（`tnet.rs`）：
  - 逐层对应 PyTorch 的 `TransformerPV`；缺失的历史步直接从序列里去掉（结果完全相同）。
  - 一致性检查 `scripts/check_tnet.py`：真实局面上我方 / 对手视角的 logits 和价值误差都在 1e-5 量级，argmax 100% 一致。**每次修改推理代码都要重跑。**
  - 性能：AVX-512 寄存器分块的矩阵乘法（4 行 × 32 输出），输入投影按 token 批量计算。单线程每次前向 496 → 约 210 µs，矩阵乘法已接近单核 fp32 峰值。
  - 对手视角的输入由我方视角变换得到，不重算伤害（测试验证与直接计算相同）。
- **搜索接入**：
  - 每个世界一个上下文：真实历史、公开信息标记、双方分数、回合数。由 `agents/net_context.py` 从对局日志构造，做法与训练数据完全相同：历史用同一个函数，我方被看到的信息用对手视角的影子 Battle。
  - 树中下降时，路径上的动作加进历史，用过的招式 / 太晶 / 换上的宝可梦标为已暴露，主步数推进回合。
- **GPU 批量搜索**（`bsearch.rs` + `agents/gpu_net.py` + `agents/gpu_search.py`）：
  - virtual loss 收集叶子，GPU 上用同一个 PyTorch 模型（fp32，TF32 关闭），和 Rust CPU 推理在同一批叶子上误差约 1e-5。
  - CUDA Graph 按固定批量录制。模型里的下标改成注册的缓冲张量后才能录制，数值不变。
  - **质量的衡量方法**：同样 0.5 秒，各配置的根节点首选与一次深搜索（单棵树 16,000 次迭代）的一致率，40 个局面。两次深搜索之间的一致率（上限）为 82%；单棵树 1k / 2k / 4k / 8k 次迭代分别为 55% / 62% / 78% / 82%。
  - **根并行（多棵独立的树）没有用**：8 棵各约 2,200 次的树，一致率只相当于一棵 2,000 次的树（62%）。所以改为**树并行**：8 个线程同时下降同一棵树（选择在锁内，指令和叶子输入在锁外），撞到等待评估节点的路径保留虚拟访问直到这批应用（冲突从每步约 4,600 次降到约 350 次），叶子的输入在各线程里直接构造（原来单独多线程计算时线程启动开销占一半时间）。
  - **结果**：批量 32 × 8 线程，每步约 1.1 万个叶子，一致率 **75%**（CPU 单线程 3,600 个叶子，65%）。批量更大时 virtual loss 的损失超过多出来的迭代数（64：70%，128：57%）。
  - 同样迭代数下，树并行的批量搜索比逐个搜索略偏（2,000 次时首选一致 85%，两次逐个搜索之间 95%），这是 virtual loss 的代价，同样时间下被更多的迭代数补回来。
  - **流水线**：GPU 算这一批时 CPU 收集下一批（两批都带 virtual loss 挂在树上），输入经锁页内存异步拷贝；输出与同步路径逐位相同。批量 32 时每步约 1.6 万个叶子（不用流水线约 1.1 万），一致率 70%、总变差 0.195（CPU 65% / 0.254）；批量 16 / 32 / 48 的差别在 40 个局面的噪声范围内。
- **对阵特征的伤害计算缓存**：一次特征计算内，同一组参数的伤害只算一次（预计招式、威胁、在场双方的招式），特征逐字节不变，88 → 67 µs。

**推理成本的手段**（按需要采用）：
- 一次前向同时给两个头，先验存进节点；
- 分层：根节点用大模型，树内用小模型；
- MTP 对手头省掉翻转前向；
- NNUE 式增量累加器、量化、virtual loss 攒批。

**训练路线**：
1. 人类数据（现在）；
2. expert iteration：搜索 + 网络自对弈，产生局面、双方根访问分布和胜负，继续训练两个头。保留人类数据并加 KL 正则（piKL），对手是"历代 bot + 模拟人类"（D14-2）。

### D14. 创新方向（待逐项验证；"新意"为当时的判断，立项前查文献）

**方向 B：隐藏信息进入搜索**

1. **双向信息建模（首选）**
   - 问题：树中对手看穿我方全部配置，导致"藏牌"（暂不太晶、不暴露克制招式）在搜索里没有价值。
   - 做法：对手先验的翻转视角前向遮住它看不到的我方信息（只留已暴露的，或换成对手视角的信念采样），之后再扩展到对手视角的价值。
   - 验证：对战场对比，并统计太晶 / 关键招式的暴露时机是否推迟。
   - MTP 对手头的训练标签来自看不到我方隐藏信息的真实对手，本身就符合这个方向。
2. **身份条件化 + 人类模型陪练**
   - 输入 = 我方身份、对方身份，各取以下之一：
     - `人类@赛前分数`：从日志末尾的 `|raw|` 分数变化行解析；不能用赛后分数，会泄露结果；
     - `bot@第 g 代`；
     - `未知`：训练时随机遮蔽。
   - 同一策略头学"分数 r 的人怎么下"（人类数据）和"第 g 代 bot 怎么下"（自对弈）；价值 = v(局面 | 我方, 对方)。
   - 用处：
     - 自对弈的陪练按比例取历代 bot 和"人类@各分数段"，分布贴近天梯；
     - classifier-free guidance 外推作为我方先验：π ∝ π(·|高分)^(1+w) / π(·|未知)^w；
     - 辅助头从历史预测对手身份 / 分数，对局中用它选对手先验。
   - 背景：训练数据的分数分布为 <1300 约 45%、1500+ 约 22%，只按分数筛数据会丢掉大半。
3. **学出来的信念网络 + 观察一致性过滤**
   - 网络输出对手配置后验，标签 = 整局最终暴露的配置；用出手顺序和伤害数值剔除矛盾世界（粒子滤波）。
   - 它是 1、2 的基础，与网络 v3 的辅助头合并考虑。
   - **决定**（2026-10-06）：
     - 保留信念模型，网络输入继续用"世界的配置 + 公开信息标记"。价值是在具体世界里评估叶子的，必须和模拟的配置一致；B 组特征也按世界的配置计算。
     - 第一个实验：对手未暴露的字段换成"未知"编号（`--mask-hidden`），对比 A + C 有 / 无信念样本，看策略、价值，以及配置头独立推断的准确率。已知偏差：对手的能力值仍来自采样的努力值分配。
     - 遮蔽机制可以直接用于 D14-1（对手先验里遮住我方未暴露的信息）。
     - v3 第一批的初步结果（10% 数据）：对手配置头在未暴露字段上，道具 61% 对信念单次采样 48%，太晶属性 41% 对 32%。但这个对比偏向网络，因为网络取最可能值、信念是随机采样一次，而且网络输入里本来就有信念样本。
     - **遮蔽实验结果**（`results.md`）：输入遮成"未知"后，策略、价值完全不变（CE 1.3979 对 1.3986）；对手配置头反而略准（道具 64.9%、太晶 42.1%），仍明显超过信念单次采样。也就是说，信念样本对网络没有额外信息，网络能独立推断。下一步按后续路线 1、2 做（网络重新加权信念候选、生成式配置模型）。搜索仍然需要信念模型提供完整的世界。
   - **后续路线**：
     1. 若网络独立推断更准：用网络给信念模型的候选配置重新加权（后验 ∝ 信念先验 × 网络打分），整套配置的一致性仍由信念模型保证。
     2. 生成式配置模型：MaskGIT 式掩码补全，以对局历史为条件逐步生成一致的整套配置。它能处理标签缺失，最终可以替代信念模型的采样器（根节点每步一次，批量计算）。
     3. 两遍推理（类似 AlphaFold 的 recycling，先预测配置分布再填回输入）：留给只看信息集的根节点网络。
4. **同时出招的博弈论搜索**：节点上用 regret matching 产生混合策略，用网络先验加速。

**方向 A：LLM 产生 MCTS 可用的先验**
5. **LLM 作分布外配置的信念先验**：冷门队伍 / 新配置上与数据模型混合，每队调用一次；用冷门队伍上的对数似然量化效果。
6. **LLM 作离线标注老师**：标注胜利路线、保留 / 牺牲、威胁，作为网络的辅助目标，推理零成本。
7. **LLM 给长期目标，塑形叶子价值**：把目标翻译成基于势函数的叶子偏置。风险最高。

**推荐顺序**：1 → 2 → 5 或 6 → 4 → 7。

1. **网络 v2 / v3 全量训练**：

## 7. 风险

| 风险 | 缓解 |
|---|---|
| 自对弈吞吐不足（Showdown + 网络推理） | 先实测端到端吞吐；必要时租多核 CPU，或自写引擎 |
| 推理拖慢搜索 | 按固定时间的胜率决定树内用哪个模型；可用分层、蒸馏、增量累加器 |
| 自对弈收敛到"对付自己" | 人类数据锚点 + KL 正则；陪练里放入人类模型（D14-2）；league |
| 人类数据的偏差 | 价值标签带噪、会学到人类错误、局面分布与 bot 不同 → 进入 expert iteration 阶段后修正 |
| 评测噪声 | 配对赛程 + 置信区间；小差别要配足局数；离线指标看种子方差 |
| poke-engine 不保真 | 只作搜索用的近似模型；fallback 记账（`search_fallbacks`）；已修过 Encore panic、预览宝可梦 1 HP 两个 bug |
| 环境变化（禁用名单、新宝可梦） | 训练按时间加权，评测用最近的对局 |
| 许可 / 规则 | Metamon 数据非商用；Foul Play 为 GPL；Showdown 对 bot 的态度模糊 |
