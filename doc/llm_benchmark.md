## 解读（2026-10-04）

样本很小（30 道配置补全、40 道属性克制、20 道速度、12 个核心中共 9 个明确标签），相差一两题不代表模型有差别。

1. **凭记忆补全配置：三个模型都远不如我们的统计先验**（"baseline(team prior)"，即第 2 步的整队条件信念先验，只用 replay 统计、不调用 LLM）。道具 top-1：83% 对 Gemini 47%、Sonnet 33%；招式 recall@4：90% 对 64%、59%。可能是 2026-10 的 metagame 与被照搬的热门队伍不在模型知识里。**结论：配置预测交给数据驱动的信念模型，LLM 不用来"猜配置"。**
2. **机制题三者持平**：属性克制 38/40、40/40、39/40，速度都是 20/20。
3. **基于数据的命名：三者都可用，Gemini 在明确标签上最好**：9 个明确标签中 Gemini 9 对 0 多标 0 漏标；DeepSeek 7/0/2、Sonnet 7/1/2，漏掉的都是"伽勒尔呆呆王的冷笑话会开雪"。改用英文输入输出加接地 prompt 后，描述核心时提到 DATA 以外招式/道具的情况基本为零（DeepSeek 的 2 次是在说明赛富豪能挡对手的 Defog 和 Rapid Spin，属于合理引用）。
4. **DeepSeek V4.1 Flash 标价便宜，实际并不便宜**：推理强度 low 时仍产生大量推理 token，批量配置补全在 16k token 上限下仍被截断（该项跳过），速度最慢。
5. **累计花费**（含调试与重试，来自账本）：Gemini 3.8 Flash 约 $0.08，DeepSeek V4.1 Flash 约 $0.09，Claude Sonnet 5.5 约 $0.20。

**模型选择（已定，2026-10-04）**：快速、批量的任务默认用 **google/gemini-3.8-flash**；对质量要求高的任务以后考虑 **Claude Opus 5.5**（需要时先在本 benchmark 和盲评上验证）。命名质量的最终判断见盲评 `doc/llm_blind_review.md`。

### 评测过程中修正的问题

- 推理模型把输出上限用在推理上导致空响应，且空响应曾被缓存：现在空/截断响应不缓存，截断时自动加倍上限重试一次，所有模型统一推理强度。
- 学习招式表缺少进化前继承的招式，导致"不合法招式"误报：改为沿进化链与基础形态合并（真实 replay 中仅剩 6/46,376 个不一致，来自 Illusion 等特殊情况）。
- 违规检测把 'Sludge Bomb' 中的 'Sludge'、'Water Absorb' 中的 'Absorb'、属性名 'Psychic' 误判为招式：改为最长匹配、排除特性名与属性名。
- 标准答案规则漏了"冷笑话（Chilly Reception）开雪"：已加入（完整队伍按队伍内重建的招式判断，其余按配置原型）。
- 部分模型把 tags 返回成逗号分隔的字符串：评分时兼容。
- 报告改为"对的题数/总题数"与计数，避免小样本下的百分比误读。
