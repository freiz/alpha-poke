## 解读（2026-10-04）

样本很小（30 道配置补全、12 个核心），下面的差异只看大的方向。

1. **凭记忆补全配置：三个模型都远不如我们的统计先验。** 道具 top-1：统计先验 83%，Gemini 47%，Sonnet 33%；招式 recall@4：90% 对 64% / 59%。原因可能是 2026-10 的 metagame 和被照搬的热门队伍不在模型知识里。**结论：LLM 不该用来"猜配置"，配置预测交给数据驱动的信念模型。**
2. **机制题三个模型都接近满分**（属性克制 95–100%，种族速度 100%），基础知识可靠。
3. **基于数据的命名：三者都可用。** 明确标签召回率都是 100%，精确率 Gemini 78%、Sonnet 88%、DeepSeek 100%（只有约 8 个明确标签，差异不显著）。改成英文输入输出加接地 prompt 后，描述核心时提到 DATA 以外招式/道具的情况**基本为零**（唯一一次是 DeepSeek 合理地提到对手的 Defog）。
4. **DeepSeek V4.1 Flash 标价便宜，但实际花费与 Gemini 相当**：即使推理强度设为 low，它也会产生大量推理 token（批量配置补全时 16k token 仍被截断，该项无法完成），速度也最慢（约 4–7 分钟一轮）。
5. **实际花费**（含调试与重试，来自账本）：Gemini 3.8 Flash $0.077（18 次调用），DeepSeek V4.1 Flash $0.075（33 次），Claude Sonnet 5.5 $0.203（17 次）。

**建议**：命名与说明用 **Gemini 3.8 Flash**（快、便宜、输出稳定），DeepSeek 作为备选；强模型目前没有明显优势，暂不需要。命名质量的最终判断见盲评 `doc/llm_blind_review.md`。

### 评测过程中修正的问题

- 推理模型把输出上限用在推理上导致空响应，且空响应曾被缓存：现在空/截断响应不缓存，截断时自动加倍上限重试一次，所有模型统一推理强度。
- 学习招式表缺少进化前继承的招式，导致"不合法招式"误报：改为沿进化链与基础形态合并（真实 replay 中仅剩 6/46,376 个不一致，来自 Illusion 等特殊情况）。
- 违规检测把 'Sludge Bomb' 中的 'Sludge'、'Water Absorb' 中的 'Absorb'、属性名 'Psychic' 误判为招式：改为最长匹配、排除特性名与属性名。
- 部分模型把 tags 返回成逗号分隔的字符串：评分时兼容。
